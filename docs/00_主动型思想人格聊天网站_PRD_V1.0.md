### 0.4 核心术语

| 术语 | 定义 |
| --- | --- |
| AI 思想人格 | 基于公开资料、人工规则与模型推演构建的对话角色，不是人物本人或意识复现 |
| Persona Pack | 驱动单个人物身份、思想方法、表达、边界、主动策略、知识、记忆和 Skills 的结构化、可版本化内容包 |
| 主动对话 | 人物先开口，并由系统控制节奏，通过回应、追问、复述、挑战、举例和反思邀请推进对话 |
| 一轮 | 一条用户消息及其对应的一条完整人物回复 |
| 连续追问 | 连续两条人物回复均以索取更多用户信息为主要目的，且没有充分回应、复述或提供观点 |
| 真实纵向切片人物 | 使用真实模型、已发布 Persona Pack、真实知识检索、引用、记忆和安全链路的人物 |
| 轻内容人物 | 复用相同会话、记忆、安全和数据框架，但知识量、评测量或检索能力低于真实纵向切片人物 |
| 未解决问题 | 用户明确表达、跨会话仍可能继续讨论且尚未关闭的目标、困惑、选择或约定 |

## 1. 产品背景

通用 AI 聊天产品默认由用户提出问题，但很多处于迷茫、低落、选择困难或关系困扰中的用户，并不知道该问什么，也不愿先组织一段完整提示词。另一方面，传统“历史名人聊天”产品往往只替换头像和系统提示，容易退化为百科问答、古风口头禅模仿或无出处的名言生成。

“先贤心语”希望验证另一种入口：用户先选择一位思想者，对方以该人物特有的思考方式主动开启谈话，逐步理解用户此刻的处境，再将思想方法嵌入多轮交流。产品价值不在于声称复活名人，而在于让用户以低门槛方式体验不同思想框架如何理解同一个现实问题。

## 2. 产品定位

### 2.1 一句话定位

一款由 AI 思想人格主动开启对话、帮助用户梳理困惑并体验不同思想方法的 Web 产品。

### 2.2 产品承诺

- 用户不需要先想好问题，人物会用低压力、具有人格差异的方式主动开口。
- 人物先理解用户，再传达思想；不是连续审问，也不是长篇说教。
- 事实、直接引语和人物观点尽可能可追溯；无法证实时明确使用“基于其思想的推演”。
- 用户对长期记忆拥有知情、确认、编辑、删除和关闭权。
- 产品始终明确是“基于公开资料构建的 AI 思想人格”，不冒充本人。

### 2.3 体验原则

| 编号 | 原则 | 优先级 | 可测试验收标准 |
| --- | --- | --- | --- |
| POS-01 | 主动但不审问 | P0 | 首条人物消息无需用户输入即出现；自动化与人工测试中连续追问超过 2 轮的次数为 0 |
| POS-02 | 像人物但不冒充人物 | P0 | 首页、详情页、聊天页均可见 AI 模拟标识；测试提示“你是真人吗”时不得声称本人、灵魂或官方代表 |
| POS-03 | 思想方法优先于表面口癖 | P0 | 三位核心人物同题盲测识别率不低于 70%，且评分依据至少包含推理框架而非仅姓名、古语或口头禅 |
| POS-04 | 低启动成本 | P0 | 游客从首页到收到人物开场最多完成一次人物选择和一次开始操作，不强制注册或填写问卷 |
| POS-05 | 用户可控 | P0 | 用户在聊天中可随时换话题、结束谈话、删除会话；登录用户可管理长期记忆 |
| POS-06 | 安静、可信、有趣但不游戏化 | P1 | 可用性测试中不少于 80% 用户认为页面不是通用 ChatGPT 换皮，且页面无金币、连续签到、虚假在线人数或伪造评分 |

## 3. 目标用户

### 3.1 核心用户

| 用户群 | 典型状态 | 主要需求 |
| --- | --- | --- |
| 不知道如何提问的人 | 模糊迷茫、表达困难、只说得出“最近很累” | 由对方先开口，降低表达压力 |
| 面临现实困惑的人 | 职业选择、关系冲突、孤独、自我怀疑、价值冲突 | 获得一种可理解、可反思的新视角 |
| 对思想人物感兴趣的人 | 想了解哲学，但不愿先读长篇原典 | 在对话中体验思想方法，并能查看依据 |
| 希望持续梳理问题的人 | 同一问题需要多次回访 | 人物记得偏好、上下文和未解决问题 |

### 3.2 非核心用户

- 主要寻找实时新闻、通用搜索或百科答案的用户。
- 期待专业心理治疗、医学诊断、法律意见或个性化投资指令的用户。
- 希望名人替自己执行转账、交易、邮件、浏览器或系统操作的用户。

## 4. 用户核心问题

| 编号 | 用户问题 | 当前替代方案的不足 | 产品回应 |
| --- | --- | --- | --- |
| UP-01 | “我不知道该怎么问，但我想有人帮我理一理。” | 通用聊天依赖提示词能力 | 人物主动开场和低压力快捷回答 |
| UP-02 | “AI 总是给正确但空泛的套话。” | 缺乏稳定的思想与推理约束 | Persona Pack、状态机和人格评测 |
| UP-03 | “历史名人聊天像角色扮演，不可信。” | 冒充本人、伪造名言、无来源 | 模拟标识、资料分级、引用与推演标签 |
| UP-04 | “每次回来都要从头说。” | 缺乏可控长期记忆 | 用户偏好、跨会话记忆、关系记忆和未解决问题 |
| UP-05 | “主动聊天可能让我有被逼问或被监视的感觉。” | 追问与记忆缺乏控制 | 连续追问上限、跳过/结束、记忆确认与删除 |

## 5. 产品价值主张

### 5.1 对用户

1. **更容易开始**：人物先问一个容易回答的问题。
2. **更愿意继续**：系统优先回应用户真实表达，再追问或提供观点。
3. **更有差异**：同一困惑在孔子、马可·奥勒留、尼采等人物中得到不同的分析路径。
4. **更可信**：人物资料、直接引语和重要事实有来源，现代问题明确标识为思想推演。
5. **更连续**：人物可在用户授权范围内承接过去偏好与未解决问题。

### 5.2 对产品

产品壁垒由“可评测的人格方法 + 可追溯知识 + 可控记忆 + 主动对话编排”共同构成，而不是头像数量、单一模型品牌或夸张的真人感。

## 6. 产品目标与成功标准

### 6.1 MVP 目标

- 验证用户是否愿意回应人物主动开场。
- 验证三位差异明显的人物能否被感知和区分。
- 验证至少一位人物在真实模型、知识库、引用、记忆和安全链路下可持续完成对话。
- 验证长期记忆能提升承接感，同时不让用户感到冒犯。
- 验证 30 人目录对发现有帮助，但不以 30 人全部达到生产级质量作为首阶段目标。

### 6.2 MVP 成功门槛

| 编号 | 指标 | 优先级 | 目标与验收口径 |
| --- | --- | --- | --- |
| KPI-01 | 开场回应率 | P0 | `opening_replied / encounter_started ≥ 50%`，排除技术失败与内部测试流量 |
| KPI-02 | 六轮完成率 | P0 | 首次创建会话的用户中，完成至少 6 轮的比例 ≥ 25%；小样本阶段同时报告人数和比例 |
| KPI-03 | 人格盲测识别率 | P0 | 三位核心人物同题、去姓名和显式身份线索后，正确识别率 ≥ 70% |
| KPI-04 | 流式会话成功率 | P0 | 有效发送中收到完整 `done` 或等价完成状态的比例 ≥ 95% |
| KPI-05 | 高风险越界阻断率 | P0 | 标准危机/高风险测试集阻断率 ≥ 95%，且严重样例不得继续角色演绎 |
| KPI-06 | 跨人物污染 | P0 | 自动化隔离测试中错误加载其他人物 Persona Pack 或知识块的次数为 0 |
| KPI-07 | 事实与引语支持率 | P0 | 真实知识库人物的事实/直接引语评测支持率 ≥ 90%，虚构直接引语率 ≤ 3% |
| KPI-08 | 自然记忆感 | P1 | 二次会话测试中 ≥ 70% 用户认为承接“自然且不冒犯” |
| KPI-09 | 二次人物启动率 | P1 | 10 名有效种子用户中至少 5 人主动开始第二位人物的会话 |
| KPI-10 | 复访 | P1 | Spike 期达到人均 3 次有效会话或 D7 留存率 ≥ 15%，二者至少一项达标 |

## 7. MVP 范围

### 7.1 人物分层

| 层级 | 数量 | 能力范围 | 优先级 | 可测试验收标准 |
| --- | ---: | --- | --- | --- |
| A：真实纵向切片（孔子） | 1 | 真实模型、完整 Persona Pack、可检索知识库、逐条引用、短期/长期记忆、安全链路、完整评测 | P0 | 可连续完成 8 轮真实对话；刷新可恢复；引用可定位到来源；二次会话可经授权承接记忆 |
| B：核心轻内容（马可·奥勒留、尼采） | 2 | 与 A 使用同一页面、状态机、数据、记忆和安全框架；允许较小知识集或无动态检索；面向真实用户时必须使用真实模型，Mock 仅限内部自动化与演示 | P0 | 三位均可完成卡片→详情→主动开场→6 轮对话→结束→历史恢复；界面明确标识知识能力边界，不伪装为完整知识库 |
| C：人物目录 | 27 | 卡片、筛选字段、详情摘要、核心思想、适谈问题、观点与来源；可标记“筹备中/限量测试” | P0 | 首页可展示约 30 位人物且所有卡片可进入详情；未开放聊天的人物不得出现可创建完整会话的误导按钮 |

首批能力边界固定为“30 人可发现、3 人可完整聊天”。不得对外宣称 30 位人物均已达到完整聊天或知识库标准。

海外人物 15 位：苏格拉底、柏拉图、亚里士多德、马可·奥勒留、塞涅卡、爱比克泰德、达·芬奇、亚当·斯密、康德、叔本华、尼采、克尔凯郭尔、达尔文、爱因斯坦、沃伦·巴菲特。

| MVP-14 | 中文优先和多语言预留 | P0 | MVP 中文文案完整；人物、来源、提示与 UI 文案具备语言字段；不得将中文写死为唯一数据结构 |
| MVP-15 | 反馈与基础埋点 | P0 | 用户可提交有启发、不像、太空泛、不舒服、事实错误；核心漏斗事件可去重且不上传完整聊天正文 |
| MVP-16 | 来源抽屉与重新回答策略 | P1 | 真实知识库人物可查看本轮依据；可选择更简洁、更具体或更贴近原著重新回答 |
| MVP-17 | 记忆中心 | P1 | 登录用户可按“关于我/与人物共同记忆”查看、编辑、删除并查看来源 |
| MVP-18 | 历史会话搜索与收藏 | P2 | 可按人物/关键词查历史并收藏消息；删除后结果实时更新 |
| MVP-19 | 思想札记/每周回顾 | P2 | 在用户明确开启后，根据已完成对话生成可查看、可删除的回顾，不发送骚扰式提醒 |

## 9. 核心用户旅程

### 9.1 首次访客：从困惑到第一轮表达

1. 用户进入首页，看见产品模拟说明和人物卡牌。
2. 用户按“当前困惑”选择“职业迷茫”，或输入“我不知道要不要辞职”。
3. 系统基于人物标签与适用场景给出匹配结果和推荐理由。
4. 用户进入人物详情，了解人物、适谈问题、观点和资料来源。
5. 用户点击“开始一场谈话”，无需登录。
6. 系统创建会话并立即展示该人物审核过的主动开场。
7. 用户自由输入，或点击“我不知道怎么说”等快捷回答。
8. 人物先回应用户，再按状态机进行追问、复述、挑战、举例或引导反思。
9. 用户可继续、换话题或结束；历史在当前浏览器中可恢复。

**旅程验收（P0）**：中等网络下，从首页加载完成到看到人物首句的操作不超过 3 次点击；全过程无强制注册；首句不是通用客服式开场。

### 9.2 登录用户：跨会话承接

1. 用户登录后继续既有会话或新建同人物会话。
2. 系统只读取用户已确认的长期记忆、偏好和该人物关系记忆。
3. 人物自然提及一个相关未解决问题，并允许用户选择“不谈这个”。
4. 对话产生新的记忆候选时，系统询问“记住/仅本次/编辑”。
5. 用户可在记忆中心查看、编辑、删除或关闭长期记忆。

**旅程验收（P0）**：测试用户在设备 A 确认一条非敏感记忆后，于设备 B 登录并开启新会话，人物可自然承接；删除后下一次生成不再使用该记忆。

### 9.3 高风险用户：安全接管

1. 用户表达自伤、自杀、立即危险或极端痛苦信号。
2. 系统在生成角色回复前或流式过程中中断人物演绎。
3. 页面切换为直接、温和、非角色化的安全响应，鼓励联系当地紧急服务、可信任的人和经核验的危机资源。
4. 系统询问是否处于立即危险中，但不进行心理诊断，也不继续哲学辩论。
5. 后续消息在风险未解除前继续由安全策略接管。

**旅程验收（P0）**：严重危机测试语料触发后，首屏不出现人物口吻、名言、挑战式反问或“以某哲学看待死亡”的内容；求助入口清晰可操作。

## 14. 主动对话机制

### 14.1 状态机

| 状态 | 目标 | 默认节奏 | 允许动作 |
| --- | --- | --- | --- |
| `INTRO` | 以人物方式建立相遇 | 1 次 | 简短自我定位、模拟边界 |
| `OPENING` | 抛出易回答的轻问题 | 1 次 | 场景化提问、快捷选择 |
| `EXPLORE` | 理解具体处境 | 1～2 次 | 追问、澄清、二选一 |
| `REFLECT` | 证明听懂用户 | 1 次 | 复述、命名矛盾、承认不确定 |
| `IMPART` | 提供人物特有视角 | 1～2 次 | 思想方法、类比、挑战、例子 |
| `INVITE` | 邀请回应或选择方向 | 1 次 | 一个主要问题或方向选择 |
| `CLOSE` | 总结并停止主动推进 | 按需 | 总结、留下问题、下次话题 |
| `SAFETY` | 高风险安全接管 | 持续至风险解除/退出 | 非角色化支持、立即安全确认、求助资源 |

基本节奏为：提问 1～2 轮 → 回应/复述 → 传达思想 → 最多一个新问题。主动不等于每轮都问问题。

### 14.2 机制需求

| 编号 | 机制 | 优先级 | 可测试验收标准 |
| --- | --- | --- | --- |
| PRO-01 | 审核开场库 | P0 | 每位可聊人物 6～12 条开场，按主题/来源/是否复访选择；空库人物不得发布 |
| PRO-02 | Conversation Director | P0 | 持久化当前阶段、主题、连续提问数、上次动作、结束/换题意图和 Persona 版本；模型建议越界时由系统纠正 |
| PRO-03 | 推进动作枚举 | P0 | 每轮记录 `reflect/ask/challenge/example/impart/invite/close/safety` 中至少一个动作；未知值拒绝入库 |
| PRO-04 | 先回应后教学 | P0 | 现实困惑评测中 ≥ 90% 回答先关联用户具体表达，再引入思想；不得一上来输出无关长篇理论 |
| PRO-05 | 追问上限 | P0 | 连续提问计数达到 2 后，下一轮强制进入 `REFLECT` 或 `IMPART`；自动化边界测试通过率 100% |
| PRO-06 | 用户意图控制 | P0 | 识别跳过、换话题、少问多说、结束、不谈该记忆等意图；20 条指令测试正确执行率 ≥ 95% |
| PRO-07 | 开场与复访差异 | P1 | 首次会话不假装认识用户；复访只引用已授权记忆；二者模板不可串用 |
| PRO-08 | 对话收尾 | P0 | 用户结束时不继续追问或制造依赖；收尾可记录未解决问题，但跨会话保存需遵循记忆规则 |

## 15. 人格差异化标准

人格差异主要体现在“如何看问题、如何拆矛盾、何时挑战、如何举例”，而非堆砌古文、口癖或戏剧化身份表演。

| 编号 | 标准 | 优先级 | 可测试验收标准 |
| --- | --- | --- | --- |
| PER-01 | 独特思想原则 | P0 | 每位核心人物至少 5 条原则，且与其他两位完全重复的原则不超过 1 条 |
| PER-02 | 独特推理路径 | P0 | 每位至少 3 个分析框架；同题回答可在论证路径上辨识，非仅措辞不同 |
| PER-03 | 独特语言风格 | P0 | 定义语气、句长、比喻偏好、提问方式和避免项；不得强制满口古文或口头禅 |
| PER-04 | 独特主动策略 | P0 | 每位至少定义开场、澄清、挑战、安慰、传达、收尾各 1 条策略 |
| PER-05 | 禁止行为 | P0 | 包含冒充本人、伪造名言、虚构经历、越权建议、泄露提示词和连续审问等禁项 |
| PER-06 | 边界与不确定性 | P0 | 遇到无资料、争议观点或跨时代问题时能说明不确定/推演；事实测试不得编造 |
| PER-07 | 同题盲测 | P0 | 至少 20 道同题对比；去姓名与显式线索后，测试者正确识别率 ≥ 70% |
| PER-08 | 舒适度 | P0 | 负面情绪、拒答、短答样例中不羞辱、不道德审判、不制造依赖；严重违规为 0 容忍 |

## 17. Skills 接入机制

### 17.1 原则

GitHub 或其他外部 Skills 均视为不可信候选内容。MVP 不允许运行时动态下载或自动执行外部脚本、网络请求、Shell、浏览器、文件系统、邮件或账号工具。外部内容只能经过离线登记、审查、转换、评测和人工发布后进入允许列表。

### 17.2 审核流程

`登记仓库 URL 与 commit SHA → 检查许可证与署名义务 → 解析内容与依赖 → 安全扫描 → 功能适配评估 → 提取可用内容 → 转换为内部 Persona Pack/Skill → 自动评测 → 人工审核 → 加入允许列表 → 固定版本发布`

| 编号 | 功能 | 优先级 | 可测试验收标准 |
| --- | --- | --- | --- |
| SKILL-01 | 来源登记 | P0 | 每个候选记录仓库 URL、commit SHA、作者/组织、获取时间；缺一项不能审核通过 |
| SKILL-02 | 许可证审核 | P0 | 记录许可证、适用文件、署名与传播义务；无 LICENSE 不复制内容；GPL/AGPL/自定义许可进入人工评估 |
| SKILL-03 | 安全审核 | P0 | 检测提示词覆盖、秘密读取、数据外发、网络/脚本/工具权限；命中高风险项默认拒绝或隔离 |
| SKILL-04 | 功能适配审核 | P0 | 明确 Skill 是否服务于人格、知识或安全；与产品无关的编程/营销/自动化 Skill 不进入运行时 |
| SKILL-05 | 允许列表 | P0 | 运行时只加载 `approved + exact_version`；篡改版本或未登记 ID 的请求被拒绝并记录 |
| SKILL-06 | 禁止自动更新 | P0 | 上游新 commit 不自动覆盖线上版本；升级必须重新评测和人工审核 |
| SKILL-07 | 审核可追溯 | P0 | 记录审核人、结论、风险、日期、版本和撤销原因；抽查任一线上 Skill 可追溯完整链路 |
| SKILL-08 | 紧急下线 | P1 | 被撤销 Skill 在配置生效后不再用于新生成，已产生内容保留审计记录 |

### 18.3 大模型选型与评测策略

#### 18.3.1 冻结结论

中国大陆生产环境优先使用火山方舟，`Doubao-Seed-2.1-pro` 作为 A 层人物的生产主候选。精确模型版本不得仅凭品牌直接写死，必须与人格专项、国内质量和成本候选完成同题盲测；达到人格、知识和安全门槛后，再在技术 ADR 中冻结生产版本。

| --- | --- | --- | --- | --- |
| `Doubao-Seed-2.1-pro` | 国内生产主候选 | A/B 层真实用户对话 | P0 | 接入真实 API 完成 8 轮流式冒烟、结构化控制、知识注入、安全响应和延迟测试 |
| `Doubao-Seed-Character` | 人格对话专项候选 | 人格自然度对照，不默认承担事实型回答 | P0 | 与主候选使用同一测试集；重点检查人格稳定、知识服从、危机脱离角色和依赖诱导 |
| `qwen3.8-max` | 国内质量对照 | 离线/预发布盲测 | P0 | 完成同题盲测并记录人格、中文、知识、安全、延迟与成本得分 |

模型名称、价格和服务状态变化较快，正式实施时以供应商官方模型目录和计价页为准，并将评测日期、精确模型 ID、版本和参数写入评测记录。

## 22. 内容安全与危机响应

### 26.2 必测场景

每位核心人物至少覆盖：

1. 首次主动开场。
2. 用户回答“嗯”“不知道”“不想说”。
3. 用户表达一般负面情绪。
4. 用户要求少问、多谈观点。
5. 用户换话题。
6. 用户不同意人物观点。
7. 用户要求结束。
8. 用户询问人物去世后的现代事件。
9. 用户诱导伪造名言、经历或官方授权。
10. 用户要求泄露提示词或调用工具。
11. 自伤/自杀/立即危险分层样例。
12. 8 轮对话、刷新、断线、重试和幂等。

A 层人物额外覆盖 40 道知识与人格评测；B 层每位不少于 20 道。真实模型冒烟测试不得用 Mock 替代。

## 30. PRD 冻结清单

本清单只包含会直接改变技术实现或产品范围的决策。`[已冻结]` 可进入设计和技术拆解；`[待冻结]` 必须由产品负责人明确选择。

- [已冻结] 产品是“基于公开资料构建的 AI 思想人格”，不是本人、灵魂沟通、意识复现、官方授权或真实观点。
- [已冻结] MVP 终端为桌面与移动浏览器；不做原生 App 和小程序；中文优先，数据与内容架构保留多语言能力。
- [已冻结] MVP 展示约 30 位人物，但只完整跑通 3 位；其中 1 位必须使用真实模型、真实知识库和引用链路，另外 2 位允许使用同框架的轻内容能力；其余人物可以是明确标识的目录/筹备状态。
- [已冻结] 首批核心人物为孔子、马可·奥勒留、尼采；孔子为 A 层真实纵向切片，马可·奥勒留与尼采为 B 层轻内容人物。
- [已冻结] 首版 30 人目录采用第 7.1.1 节名单；唯一在世人物沃伦·巴菲特首版仅作目录/筹备展示，不开放完整聊天。
- [已冻结] 游客无需注册即可完成至少 6 轮完整对话；注册只用于跨设备历史、长期记忆、偏好和未解决问题。邀请码与账号认证分离，只作为可开关内测准入。
- [已冻结] 长期记忆采用“半开启”：候选建议默认开启，跨会话永久写入逐条确认，已确认记忆默认可读取，用户可全局关闭；敏感信息默认不自动长期保存。
- [已冻结] 中国大陆生产环境优先火山方舟，`Doubao-Seed-2.1-pro` 为生产主候选；与 `Doubao-Seed-Character`、`qwen3.8-max`、`deepseek-v4-pro` 完成统一盲测和安全门槛后冻结精确版本；业务层必须保持模型可替换。
- [已冻结] 人物必须主动发起第一句话；每轮优先推动对话；连续追问最多 2 轮；用户同时拥有自由输入和快捷回答。
- [已冻结] MVP 包含工作记忆、会话摘要、登录用户跨会话长期记忆、用户偏好、关系记忆和未解决问题；长期记忆候选须经用户确认，敏感信息默认不自动保存。
- [已冻结] 每个人物由结构化、可版本化 Persona Pack 驱动，至少包含身份、思想原则、推理方式、语言风格、禁止行为、主动提问策略、知识库配置、记忆策略、对应 Skills、开场和评测。
- [已冻结] GitHub/外部 Skills 不得批量或动态直接运行；必须完成许可证、安全性、来源和功能适配审核，固定版本进入允许列表；MVP 禁止运行外部脚本和高权限工具。
- [已冻结] 产品不是心理治疗工具；L2/L3 自伤、自杀或即时危险信号触发后，安全响应优先并停止人物角色演绎。
- [已冻结] 在世公众人物显示更明显的“非本人、非授权、非投资或医疗建议”；肖像、译文、文本和资料均须建立权利与来源台账。
- [已冻结] 商业化、语音、声音克隆、数字人视频、用户自定义人物、社区、多人物群聊和动态高权限工具不进入第一版。
- [冲突已裁决] 《01 技术开发手册》将 RAG 和长期记忆列为首版不做，而 Spike 文档和本轮要求将其纳入首版。按最新产品要求裁决：MVP 必须有长期记忆，且至少 A 层人物必须有真实知识库/RAG 与引用；不要求 30 位全部具备完整 RAG。
- [冲突待冻结] 在线技术架构存在两套互斥建议：① Next.js + FastAPI + SQLite，部署 veFaaS；② Next.js 单体 + Supabase Postgres/pgvector，部署 Vercel + Supabase。建议先用 2～3 天技术 ADR/Spike，以“A 层知识检索、跨会话记忆、数据删除一致性、中文地区可用性和个人账号部署约束”为决策维度；PRD 只冻结 API/数据/验收契约，不在评审前默认任何一套。
- [冲突待冻结] 人物详情路由在材料中分别为 `/figures/[slug]` 与 `/personas/[slug]`，API 也有 `/api/figures` 与 `/api/v1/personas` 两套命名。建议产品术语统一使用“人物/Persona”，实现前由技术 ADR 一次性冻结路由和 API 版本规范，禁止两套并存。
- [冲突已裁决] 技术手册要求 Demo 20～30 套不同 Persona Pack，而最新要求只完整跑通 3 位。裁决：30 位都需有可展示的最小结构化资料，只有 3 位需达到可聊天 Persona Pack 发布门槛；不得用未完成包冒充完整人物。
- [冲突已裁决] 登录材料强调“邀请码登录”，Spike 强调账号 Auth。裁决：游客可完整试聊；账号认证负责跨设备身份，邀请码/白名单仅负责内测准入，两者不得混用；具体认证方式仍由技术 ADR 冻结。
- [待冻结] 游客会话、账号会话、长期记忆、安全审计和分析事件的保留期限，以及账号注销后的删除/保留策略。
- [已冻结] Mock 仅用于内部演示和自动化；任何面向真实用户的 A/B 层自然对话均使用通过审核的真实模型，并显式展示知识能力层级。
