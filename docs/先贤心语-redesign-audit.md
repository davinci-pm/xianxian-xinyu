# 先贤心语前端重构审计

> Phase 0 基线，2026-08-28。产品范围与验收以冻结 PRD 为准，视觉与交互以“先贤心语-交互设计与 Codex 执行包”为准。

## 1. 当前技术栈与运行状态

- 前端：Next.js 16.3.3（App Router）、React 19.2.8、TypeScript 5、Tailwind CSS 4（仅作为全局导入，现有页面主要使用手写 CSS）。
- 测试：Vitest 4.1.11、Playwright 1.62.1；当前只有 SSE 单元测试和旧版纵向链路 E2E。
- 后端：FastAPI + SQLAlchemy + SQLite，当前本地 `http://127.0.0.1:8765` 健康检查正常，共 19 位人物。
- 模型：后端显示 `openai_compatible`，前端只通过 `/api/backend/*` 反向代理访问，不直接依赖模型厂商。
- 前端：当前本地 `http://127.0.0.1:3000` 可访问。
- 工作区：仓库内容整体处于未跟踪状态，无法用 Git 历史判断文件归属；所有现存文件按用户资产保留，不执行覆盖式清理。
- Next.js 16 约束：动态路由 `params` 为 Promise；交互组件与浏览器存储位于 Client Component；动态路由补 `loading.tsx`；本次实现遵循本地 `node_modules/next/dist/docs` 文档。

## 3. 必须替换或新增的能力

- 全局导航、页面容器、人物视觉组件、徽标、按钮、抽屉、Toast、骨架屏、空状态。
- 首页首屏、当前困惑输入、组合筛选与清空、人物推荐、继续对话。
- 思想路径 `/paths`：三步渐进式问答与人物推荐；MVP 使用前端规则分析，最终创建真实会话。
- 人物详情 `/figures/[figureId]`：首屏双栏、主动开场预览、思想/适合讨论/资料来源标签页。
- 正式聊天：桌面三栏、移动单栏、阶段轨迹、引用抽屉、记忆抽屉、停止生成、失败重试、结束并生成札记。
- 札记 `/notes` 与 `/notes/[noteId]`：基于真实会话生成前端札记、自动保存、离线草稿、导出、继续对话。
- 记忆设置 `/settings/memory`：读取后端真实已确认记忆；暂停、编辑、删除作为本地覆盖层实现并明确适配边界。

## 5. 数据与接口边界

### 真实后端

- `GET /session`
- `GET /personas`、`GET /personas/{slug}`
- `POST /conversations`、`GET /conversations`、`GET /conversations/{id}`
- `POST /conversations/{id}/messages/stream`（SSE）
- `GET /memories`、`POST /memories/{id}/confirm`
- `GET /skills`

### 前端本地适配层

- 思想路径结果：规则匹配人物的真实 topics/dilemmas/domains，不伪造模型结论。
- 札记：由真实会话消息和摘要生成，存入 `localStorage`；后端增加札记 API 后可替换 adapter。
- 记忆暂停/编辑/删除：后端当前只有读取和候选确认，MVP 用 `localStorage` 覆盖层隐藏或改写展示，不宣称已删除服务器数据。
- 游客偏好：筛选、最近思想路径、札记草稿存储在当前浏览器。

## 6. 依赖变更

- 首选零运行时 UI 依赖：使用语义化 HTML、原生 `<dialog>`/抽屉结构和内联 SVG 图标，避免把设计系统绑定到第三方组件库。
- 单元/组件测试需补 `jsdom`、`@testing-library/react`、`@testing-library/dom`、`@testing-library/user-event`、`@vitejs/plugin-react` 与 `vite-tsconfig-paths`。
- 不引入远程字体请求；中文字体使用系统宋体/黑体栈，避免隐私与首屏性能风险。

## 7. 视觉基线与目标差距

- 基线截图：`docs/redesign-evidence/phase-0/home-desktop.png`、`home-mobile.png`。
- 当前首屏缺少主导航、真实视觉叙事和思想路径入口；人物以大字占位，19 张卡片连续铺开，移动端页面过长。
- 详情页缺少标签式内容组织和开场预览；聊天仅两栏，缺少右侧过程/引用/记忆面板；札记与记忆设置不存在。
- 重构目标采用纸张背景、墨色正文、朱砂主操作、暖金辅助和稳定的内容密度；桌面与移动分别组织，不进行桌面三栏的机械缩放。

## 8. 风险与降级

| 风险 | 影响 | 降级方案 |
| --- | --- | --- |
| 人物独立立绘素材未随执行包提供 | 不能直接复用目标图中的人物画 | 使用原创的统一“纸刻头像”视觉组件，确保无破图、构图稳定；后续可无缝替换 `/public/characters/*`。 |
| 模型首 token 慢或失败 | 对话等待感强 | 立即插入思考态、支持停止；沿用后端人物风格降级回复与显式状态。 |
| 后端缺少札记 API | 札记无法跨设备 | 通过 adapter 存本地并显示“仅此设备”，保留真实 conversationId。 |
| 后端缺少记忆修改/删除 API | 设置页操作不是服务器级删除 | 本地覆盖层明确标识；真正删除前不显示“服务器已删除”。 |
| 浏览器插件缓存版本不一致 | 无法使用插件自带控制客户端 | 使用仓库已安装 Playwright Chromium 执行同尺寸截图和 E2E；截图证据仍写入仓库文档目录。 |
| 19 位人物资料密度不一致 | 卡片与详情视觉高度波动 | 统一内容截断与空态；P0 先精修孔子、尼采、马可·奥勒留，所有人物保持可访问。 |
