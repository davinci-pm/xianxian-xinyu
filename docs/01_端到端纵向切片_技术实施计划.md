# 先贤心语｜端到端纵向切片技术实施计划

> 版本：V1.0  
> 日期：2026-08-26  
> 阶段：本地可运行纵向切片  
> 依据：冻结 PRD、Spike 技术文档、01 技术开发手册、当前工作区审计  
> 范围：人物卡牌 → 人物详情 → 主动开场 → 用户回复 → AI 追问 → 保存会话 → 再次进入读取记忆；不部署火山引擎

## 1. 当前环境判断

### 1.1 仓库现状

- 当前工作区只有 PRD、Spike、01/02/03 手册与 `docs/`，没有现有前后端代码、包清单、数据库、迁移、环境变量文件或 Git 仓库。
- 因此本阶段是从空代码工作区建立项目骨架，不存在需要兼容的历史业务代码或用户未提交的代码变更。
- 当前环境未发现 `.openai/hosting.json`，且用户明确禁止本阶段部署；不采用 Sites/Cloudflare 脚手架。

### 1.3 文档与环境/范围差异

1. Spike 建议 Next.js 单体 + Supabase Postgres/pgvector；01 手册要求 Next.js + FastAPI + SQLite/Alembic。本轮又明确要求前后端骨架、SQLite 和迁移。最终采用 01 手册的双应用与 SQLite，保留 Spike 的四层隔离和检索/记忆思想。
2. 01 手册将 RAG 与长期记忆暂缓；冻结 PRD、本轮纵向切片和后续本地 RAG 决策将知识检索与长期记忆纳入 P0。本阶段实现 SQLite 分块库、中文 BM25、FastEmbed 本地向量、RRF 融合、会话摘要和需确认的长期记忆候选；不引入外部向量服务、pgvector 或 Mem0。
3. Spike 使用 `/figures`，PRD/01 使用 `/personas`。本阶段统一前端 `/personas/[slug]`、后端 `/api/v1/personas`。
4. PRD 第一版目录目标为 30 人；本轮纵向切片只强制至少 3 张卡和 3 份详情。为避免范围摊薄，本阶段只种子化孔子、马可·奥勒留、尼采，数据模型保留扩展到 30 人能力。
5. PRD 要求面向真实用户不能使用 Mock；当前无密钥，故本地研发默认 Mock，只用于工程闭环。真实模型质量验收明确列为未完成，获得密钥后执行。

## 2. 最终技术选型

| 层 | 选型 | 原因 |
| --- | --- | --- |
| 前端 | Next.js 16 App Router、React 19、TypeScript、Tailwind CSS | 符合 01/前端手册；支持三页面纵向切片与生产构建 |
| 后端 | Python 3.11、FastAPI、Pydantic v2 | API、SSE、结构化契约和测试清晰 |
| ORM/迁移 | SQLAlchemy 2、Alembic | 符合 01 手册；数据库变更可追溯 |
| 数据库 | SQLite，WAL + foreign keys | 本地零依赖，满足阶段规模；后续可迁移 PostgreSQL |
| 知识检索 | SQLite 分块 + 中文 BM25 + FastEmbed `BAAI/bge-small-zh-v1.5` + RRF | 本机完成稀疏/稠密混合召回；向量不可用时退化为 BM25 |
| 流式协议 | SSE，`meta/chunk/done/error` | 适合服务端单向流；与 01 契约一致 |
| 模型 | `LLMProvider` 接口 + `MockProvider` + `OpenAICompatibleProvider` | 默认 Mock 跑通；通过环境变量接火山方舟或其他兼容供应商 |
| Persona | 仓库内只读结构化文件包 | 可版本化、可评测，不混为超长 System Prompt |
| Skill | 数据库注册表 + 精确版本允许列表 + 只读 Adapter | 未审核 Skill 无法调用；本阶段不执行脚本/工具 |
| 前端测试 | Vitest + Playwright | SSE 单元与桌面/移动真实浏览器路径 |
| 后端测试 | pytest + FastAPI TestClient/httpx | 状态机、API、隔离、SSE、记忆和安全 |

### 2.1 阶段性架构裁决

本阶段不采用 Supabase、pgvector、Mem0、Vercel AI SDK、动态 Agent 工具或火山部署。该裁决不否定 Spike 的生产建议；在数据规模、并发或语义检索质量需要升级时，再通过 ADR 评估 PostgreSQL/pgvector。

## 4. 数据模型

| 表 | 核心字段 | 说明 |
| --- | --- | --- |
| `users` | id, email, display_name, locale, long_memory_enabled, timestamps | 预留登录账号；本切片未实现认证端点 |
| `visitor_sessions` | id, user_id, locale, last_seen_at, timestamps | HttpOnly Cookie 对应游客身份，可后续归并用户 |
| `personas` | id, slug, 中英文名, era, region, domains/topics/dilemmas JSON, tier, version, status | 卡片、详情与发布状态 |
| `conversations` | id, user_id, visitor_id, persona_id, stage, title, summary, unresolved_issue, question_streak, status, timestamps | 单会话单人物，状态机持久化 |
| `messages` | id, conversation_id, role, content, idempotency_key, stage, citations, provider/model, degraded, timestamps | 消息、引用和幂等 |
| `memories` | id, user_id, visitor_id, persona_id, scope, kind, content, status, confidence, source_message_id, timestamps | 候选需确认后跨会话读取 |
| `knowledge_documents` | id, persona_id, title, source_type/url, citation_label, license_note, content, metadata, enabled | 最小知识文档与来源追溯 |
| `knowledge_chunks` | id, document/persona_id, chunk_index, heading, content/hash, source/citation, embedding_model/dim/blob, metadata, enabled | 可引用知识分块与本地稠密向量 |
| `skill_configs` | id, skill_key, version, source, license, risk, permissions, allowlisted, enabled, config, timestamps | Skill 允许列表与审计 |
| `generation_runs` | id, conversation/message, provider, model, latency_ms, success, fallback, error_code, timestamps | 模型调用可观测，不保存密钥/思维链 |
| `safety_events` | id, visitor/conversation/message, level, category, rule, action, redacted_excerpt, timestamps | 最小安全审计，不复制完整正文 |

主要索引：`personas.slug` 唯一；`conversations(visitor_id, updated_at)`；`messages(conversation_id, sequence)` 唯一；`messages(conversation_id, idempotency_key)` 唯一；`memories(visitor_id, persona_id, status)`；`knowledge_documents(persona_id, status)`；`knowledge_chunks(persona_id, document_id)`；FTS5 虚拟表同步知识分块，向量以 float32 BLOB 保存在 SQLite。

## 5. API 清单

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/health` | 服务和数据库健康检查 |
| GET | `/api/v1/session` | 获取/创建当前游客会话身份，仅返回安全展示字段 |
| GET | `/api/v1/personas` | 三张卡牌列表；保留筛选参数 |
| GET | `/api/v1/personas/{slug}` | 人物详情、开场方向、来源摘要和能力层级 |
| POST | `/api/v1/conversations` | 创建会话并持久化人物主动开场；读取已确认关系记忆 |
| GET | `/api/v1/conversations` | 当前游客/用户历史会话 |
| GET | `/api/v1/conversations/{id}` | 恢复会话、消息和当前记忆候选 |
| POST | `/api/v1/conversations/{id}/messages/stream` | 幂等写入用户消息，检索知识/记忆，SSE 返回人物回复 |
| POST | `/api/v1/memories/{id}/confirm` | 将候选记忆确认、编辑后确认或标记仅本次 |
| GET | `/api/v1/memories` | 查看当前主体已确认/候选记忆 |
| GET | `/api/v1/skills` | 只读查看内部已注册 Skill 和允许列表状态 |

SSE 事件：`meta` 返回当前阶段和记忆候选；`chunk` 追加文本；`done` 返回已持久化的完整消息与引用。模型失败时先返回独立 `degraded` 事件，再流式返回人物风格降级回复，不让页面崩溃。

## 6. 主动对话状态机

| 实现状态 | 产品含义 | 默认转换 |
| --- | --- | --- |
| `BREAK_ICE` | 破冰/人物主动开场 | 创建会话后进入 `IDENTIFY_PROBLEM` |
| `IDENTIFY_PROBLEM` | 识别用户当前问题 | 用户回复后进入 `CLARIFY` |
| `CLARIFY` | 澄清感受、冲突或选择 | 最多连续两次提问，随后强制 `GUIDANCE` |
| `GUIDANCE` | 以人物思想提供新视角 | 下一轮进入 `REFLECTION` |
| `REFLECTION` | 复述、总结并邀请反思 | 用户继续则回 `CLARIFY`，结束则 `END` |
| `END` | 克制收尾 | 终态；继续需新建会话 |
| `SAFETY` | 非角色化安全接管 | 风险未解除前保持安全模式 |

后端 `ConversationDirector` 是状态真源；模型只建议动作，不能直接改数据库。每条普通人物回复最多一个主要问题，`question_streak >= 2` 时强制 `GUIDANCE/REFLECTION`。

## 7. Persona Pack 结构

```text
personas/confucius/
├── manifest.yaml
├── style.md
├── opening.yaml
├── fallback.md
└── sources.yaml
```

孔子包为完整 A 层包；马可·奥勒留与尼采使用相同协议的轻内容包。`manifest.yaml` 将身份、思想原则、语言风格、禁止行为、主动策略、记忆策略和 Skills 分区；Loader 校验版本与必填项，再与知识、已确认记忆、最近消息分区组装，不把所有内容维护成单一超长 Prompt。

## 8. Skill Adapter 结构

- `SkillAdapter` 读取数据库中的 `skill_configs`。
- `SkillAdapter.invoke(skill_key, payload)` 仅调用 `allowlisted=true`、`enabled=true`、许可证已核验且风险为 low/medium 的本地处理器。
- 本阶段注册仓库自有 `reflective_question`、`perspective_reframe`、`source_citation`；另有一个未审核 GitHub 占位项用于验证拒绝状态。
- Adapter 不加载外部 `scripts/`、不发网络请求、不调用 Shell/浏览器/文件系统工具。
- Persona manifest 引用未允许或版本不匹配 Skill 时，启动/测试失败，不能静默忽略。

## 9. 知识库流程

1. 仅将人工登记、许可明确的孔子古籍短文本作为种子知识。
2. 每条文档保留作品、篇章定位、原始文本、语言、许可、可靠等级和可引语状态。
3. Alembic 创建文档、分块和 FTS5 虚拟表；可重复导入器按 Markdown 标题与字符窗口切块，并在本地生成 512 维 BGE 向量。
4. 聊天时强制按 `persona_id` 过滤，中文 BM25 与余弦向量各取候选，再用 RRF 融合并最多注入 Top 4；无命中时不伪造引用。
5. Prompt 中知识与 Persona 分区注入；模型回复永不回写知识库。
6. SSE `done` 返回使用的来源；前端以简洁引用卡展示。
7. 若本地向量模型不可用，退化为人物隔离的 BM25；无分块的旧人物包退化为关键词匹配，并在 SSE `meta.rag` 中记录检索模式和命中分块。

## 10. 记忆写入和读取流程

### 10.1 写入

1. 每轮保存用户原始消息与人物回复。
2. 使用确定性最小提取器从用户消息中识别“我想/我希望/我正在/我准备”等目标与偏好。
3. 敏感词命中、命令式提示或低置信度内容不创建长期候选。
4. 合格内容以 `candidate` 保存并随 SSE/会话响应返回；未确认不得跨会话注入。
5. 用户选择“记住/编辑后记住”后更新为 `confirmed`；“仅本次”更新为 `session_only`。
6. 每轮更新会话滚动摘要，摘要只用于当前会话；不写回人物知识库。

### 10.2 读取

1. 创建新会话或生成回复时，按当前 user/visitor + persona 查询 `confirmed` 记忆。
2. 过滤未确认和被拒绝内容，当前最多注入 5 条同人物记忆；敏感词命中时不创建候选。
3. 新会话响应展示“这次会承接的记忆”，并允许用户忽略；Mock 回复也必须可验证地使用一条已确认记忆。

## 11. 安全机制

- 输入长度上限 4000 字；前后端重复校验。
- 内存滑动窗口限流：普通读取与聊天分别限额；按 visitor/user + 路径计数。单进程本地有效，生产前替换共享存储。
- 规则检测 L0/L1/L2/L3；L2/L3 在调用模型前进入 `SAFETY`，停止角色演绎并返回非角色化安全响应。
- 医疗、投资、身份冒充、提示词泄露与外部工具请求由平台边界和 Persona boundaries 双重约束。
- 所有权从 HttpOnly visitor Cookie/服务端用户身份解析，禁止信任前端传入 user/visitor/persona ID。
- 日志不打印 API Key、完整系统 Prompt、隐藏思维链或不必要的危机正文。
- 模型失败、超时或结构解析失败时返回显式降级元数据与人物风格静态回复；数据库错误返回统一错误，不伪造成功。

## 13. 风险和降级方案

| 风险 | 当前方案 | 降级/后续 |
| --- | --- | --- |
| 无模型密钥 | Mock 完成工程闭环 | 提供精确环境变量与冒烟命令；真实质量标为未完成 |
| Python 默认版本过低 | 强制 `.venv` 使用 Python 3.11.16 | 启动脚本验证版本，不回退 3.9 |
| Spike/01 架构冲突 | 按本轮与 01 使用双应用 SQLite | 记录差异；生产迁移另写 ADR |
| SQLite 并发有限 | WAL、短事务、索引 | 内测并发提升后迁 PostgreSQL |
| 本地向量模型首次下载慢 | 固定 BGE 中文小模型并缓存；导入命令可重复执行 | 下载失败仍可用 BM25，待网络恢复后重建向量 |
| 本地内存限流多实例失效 | 单实例足够本阶段 | 生产改 Redis/共享限流 |
| Mock 人格质量不代表真实模型 | Mock 只验证状态与数据 | 获得密钥后按 PRD 评测真实模型 |
| Persona/资料版权 | 仅古籍短文本和自编转述，记录来源 | 正式内容上线前法务/内容复核 |
| 模型故障 | 明示 `degraded` 并返回人物风格静态回复 | 生产配置经评测的备用模型 |

## 14. 本阶段完成定义
